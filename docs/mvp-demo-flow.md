# 自营商城 MVP 1.0 演示流程（非技术人员版）

本文说明在浏览器里如何完成一次「能讲清楚」的自营商城演示：谁在哪个页面点什么、会看到什么。
默认前端开发地址为 `http://localhost:5173`（以实际部署为准），左侧深蓝菜单分为 **用户端** 与 **后台管理** 两组。

一期定位为 **自营商城 MVP 1.0**——由平台自己上架商品、用户下单购买、后台处理订单流转。商家入驻 / 平台治理等能力在本期作为结构预留，不在演示路径中出现。

---

## 演示前请确认

- 已启动后端（默认 `http://localhost:8080`）与前端，且前端能正常打开商品列表。
- 准备好两个演示账号（均为「用户 ID + 统一口令」登录，无单独注册页）：
  - **管理员**：用户 ID 必须在后端配置 `mall.auth.admin-user-ids` 中（默认常见为 **1**）。
  - **普通买家**：例如种子数据中的 **1001**（或任意非管理员用户 ID）。
- 已执行 `db/init/alter_unify_self_shop_seed.sql`（将商家店示例数据迁到自营店）和 `db/init/alter_add_user_address.sql`（建立地址簿表）。

**登录口令**：与后端配置一致，默认多为 **`mvp-demo`**（可被环境变量 `MALL_AUTH_LOGIN_PASSWORD` 覆盖）。

---

## 步骤 1：打开商城，确认能逛商品

| 角色 | 操作 |
|------|------|
| 所有人 | 浏览器打开前端首页，进入 **用户端 → 商品列表** |
| 预期结果 | 表格中出现自营旗舰店的商品名称、价格、库存；右上角显示 **「未登录」** 属正常 |

本步**不要求登录**。

---

## 步骤 2：买家登录

| 角色 | 操作 |
|------|------|
| 买家 | 右上角点 **「登录」**，填「用户 ID」**1001**、「口令」**mvp-demo**，点 **「登录」** |
| 预期结果 | 右上角显示 **「userId=1001 / role=USER」**；左侧菜单保持「用户端 / 后台管理」两组 |

---

## 步骤 3：维护收货地址

| 角色 | 操作 |
|------|------|
| 买家 | 左侧 **用户端 → 我的地址** |
| 点击操作 | 点右上 **「+ 新增地址」**，填写收货人、手机号、省/市/区、详细地址，勾选「设为默认地址」→ **保存** |
| 预期结果 | 列表出现新地址卡片，右上有蓝色 **默认** 标签；可再新增若干地址演示「设为默认」切换 |

---

## 步骤 4：加入购物车并编辑数量

| 角色 | 操作 |
|------|------|
| 买家 | 左侧 **用户端 → 商品列表**；进入任一商品详情，点 **「加入购物车」** |
| 访问页面 | 左侧 **用户端 → 购物车** |
| 点击操作 | 在购物车行中使用 **「−」/「+」** 按钮修改数量；可选一行点 **「删除」** |
| 预期结果 | 合计金额随数量变化；失效商品（如下架样例）以灰色显示并打上「已失效」标签，无法参与结算 |

---

## 步骤 5：买家提交订单并模拟支付

| 角色 | 操作 |
|------|------|
| 买家 | 点购物车页底部 **「去结算」** 或左侧 **用户端 → 提交订单** |
| 点击操作 | 在 **收货地址** 区选择一条地址（默认已选中默认地址），可填写备注 → 点 **「创建订单」**；看到订单号与 **待支付** 状态后，再点 **「模拟支付最新订单」** |
| 预期结果 | 提示 **「支付成功」**，状态变为 **PAID（已支付）** |

---

## 步骤 6：管理员发货

| 角色 | 操作 |
|------|------|
| 管理员 | 退出买家，重新用管理员账号（用户 ID **1**）登录 |
| 访问页面 | 左侧 **后台管理 → 订单列表** |
| 点击操作 | 找到刚才的 **PAID** 订单，进入详情或发货入口，输入 **快递单号** 与发货备注，确定 |
| 预期结果 | 订单状态变为 **SHIPPED（已发货）**，写入快递单号与发货时间 |

> 提示：一期后台发货动作复用 `/api/merchant/orders/{id}/ship` 主订单发货接口；管理员账号有权限直接调用。

---

## 步骤 7：买家确认收货

| 角色 | 操作 |
|------|------|
| 买家 | 用 **1001** 重新登录 |
| 访问页面 | 左侧 **用户端 → 我的订单** |
| 点击操作 | 找到 **SHIPPED** 状态的订单，点 **「确认收货」**，确认 |
| 预期结果 | 状态变为 **COMPLETED（已完成）**，显示完成时间；订单详情中可以看到收货人 / 手机 / 地址快照 |

---

## 演示小结（可照着念）

1. **买家**：登录 → 维护收货地址 → 浏览 → 加购（可调数量/删除）→ 选地址下单 → 模拟付款 → 等发货 → 确认收货。
2. **管理员**：登录 → 订单列表 → 发货 → 可按需下架违规商品。

整条链路对应一期"自营商城 MVP 1.0"的核心目标：一套标准的单店自营交易内核，结构允许后续无痛升级到平台型商城。

---

## 常见问题（给演示辅助人员）

| 现象 | 可能原因与处理 |
|------|----------------|
| 点后台菜单又回到商品列表 | 当前登录用户 **不是管理员 ID**，请用配置中的管理员用户重新登录 |
| 创建订单失败：收货地址不存在 | 未选择地址或选了他人地址；回到步骤 3 新增并设为默认 |
| 修改购物车数量失败：商品已失效 | 对应商品已被下架 / 删除；先删除该购物车行再继续 |
| 模拟支付失败 | 订单状态非 **PENDING_PAYMENT**；检查步骤 5 是否已支付过 |
| 登录口令不对 | 与运维确认 `mall.auth.login-password`，与登录页填写一致 |

更细的接口与数据表说明见：`docs/mvp-api-reference.md`、`docs/mvp-acceptance-checklist.md`。
