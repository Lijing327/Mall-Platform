《订单详情页设计稿（管理端）》
一、页面定位

订单详情页不是展示页，而是：

后台订单处理页

它的核心任务是：

看清楚这是一笔什么订单
看清楚买了什么商品
看清楚寄给谁
看清楚支付与发货状态
在需要时执行发货操作

所以它不是单纯把字段堆出来，而是要把信息按业务分块，让后台一眼能处理。

二、页面目标

这一期订单详情页至少要支持：

查看订单基础信息
查看订单状态
查看商品明细
查看收货信息
查看金额信息
查看支付信息
未发货时执行发货
已发货时查看发货信息

如果后面扩展，可以再加：

订单备注
操作日志
售后信息
退款信息

但当前一期先不必做全。

2. 订单状态总览区

这一块非常重要，应该放在页面最上方，优先展示。

作用

让后台一眼知道：

订单当前到哪一步了
能不能发货
下一步该做什么
建议显示内容
订单状态
下单时间
支付时间
发货时间
完成时间
状态展示建议

前端不要直接显示：

PENDING_PAYMENT
PAID
SHIPPED
COMPLETED

而是转成中文业务标签：

待支付
待发货
已发货
已完成

你当前盘点里已经说明，前后端现在更多直接用英文枚举，这能跑，但产品感不够。

状态总览示例
当前状态：待发货

下单时间：2026-04-11 14:50:31
支付时间：2026-04-11 14:52:10
发货时间：-
完成时间：-
页面表现建议
用状态卡片或横向信息条
当前状态字体和标签明显
让操作人先看到“现在该干嘛”

这个区域展示订单本身的标识信息。

建议字段
订单号
订单ID
用户ID / 用户名
订单状态
支付方式
订单来源（可选，一期没有可不展示）
建议结构
基础信息
--------------------------------
订单号：2026041111450282001
订单ID：128
用户ID：10001
订单状态：待发货
支付方式：模拟支付
设计建议
左右两列展示即可
一行两个字段最稳
不要一长列往下堆
4. 收货信息区

这是当前一期最需要补强的部分之一。

因为后台发货，最重要就是知道：

发给谁
电话多少
地址在哪

你当前盘点已经明确指出：下单时收货信息还没有完整接入，订单里 receiver_* 可能为空。

所以这一区域设计上必须先预留好，后面你一补数据，这页立刻就像正式系统。

建议字段
收货人
联系电话
收货地址
建议结构
收货信息
--------------------------------
收货人：张三
联系电话：138xxxx8888
收货地址：河北省 保定市 竞秀区 xxx街道 xxx号
空状态处理

如果当前没有数据，不要直接展示空白。

建议显示：

收货信息暂未完善

或者：

暂无收货信息

不要把 null、-、空字符串直接原样扔上去。

这是订单详情页里最重要的业务区之一。

作用

买了什么
买了几件

总金额是多少
建议采用表格

字段建议：

小计

8. 发货信息区 / 发货操作区

这是管理端订单详情页的核心操作区。

建议根据状态分两种情况展示。

场景 A：待发货

如果订单状态是“待发货”，这里应该显示发货表单。

建议字段

发货备注

发货备注
[________________________]

[确认发货]
设计建议
表单不用太复杂
单号和备注足够
按钮要明显
放在页面下半部分但不能太靠下

你当前后端已经有 shipping_no、shipping_remark、ship_time 字段，并且发货接口是真实落库的，这个区域完全值得做正式。

场景 B：已发货 / 已完成

如果订单已经发货，则显示发货信息，不再展示表单。

建议字段
物流单号
发货备注
发货时间
结构示例

--------------------------------

六、页面状态设计

为了像产品，这页至少要考虑下面几种状态。

1. 加载中

页面请求订单详情时：

显示骨架屏
或
显示“订单加载中...”

不要白屏。

2. 订单不存在

如果订单 ID 错误或查不到：

订单不存在或已删除
[返回订单列表]
3. 收货信息为空

显示统一空态文案：

暂无收货信息

不要把空字段硬展示成一堆 -。

4. 商品明细为空

如果订单异常缺少明细：

暂无商品明细
5. 已发货不可重复发货

按钮禁用或不显示：

该订单已发货
七、建议拆的后台组件

为了后面可维护，建议把这页拆成小组件。

推荐组件
1）OrderStatusPanel

展示状态、下单时间、支付时间等。

2）InfoBlock

通用信息块，用于基础信息、收货信息、支付信息、金额信息。

3）OrderItemsTable

订单商品表格。

4）ShipmentForm

待发货时的表单。

5）ShipmentInfo

已发货后的只读信息。

6）OrderAmountSummary

金额信息块。

组件结构示意
AdminOrderDetailPage
 ├─ OrderStatusPanel
 ├─ InfoBlock（基础信息）
 ├─ InfoBlock（收货信息）
 ├─ OrderAmountSummary
 ├─ InfoBlock（支付信息）
 ├─ OrderItemsTable
 ├─ ShipmentForm / ShipmentInfo
 └─ FooterActions
