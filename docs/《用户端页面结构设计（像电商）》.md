《用户端页面结构设计（像电商）》
一、设计目标

用户端不是“功能菜单页”，而是要像一个正常商城。

这一期用户端的核心目标不是做花哨首页，而是先把 购买链路做顺：

用户能快速看到商品
用户能进入商品详情
用户能顺畅加入购物车
用户能完成下单
用户能查看订单与收货状态
用户能管理地址

所以页面设计原则是：

像商城，不像后台
操作路径短
购买动作突出
信息层级清楚
先保证成交链路，再补内容运营
二、用户端页面清单

一期建议用户端固定为这 7 个核心页面：

商品列表页
商品详情页
购物车页
提交订单页
我的订单页
地址管理页
登录页

建议路由如下：

/products
/products/:id
/cart
/checkout
/orders
/addresses
/login

首页 / 可先直接重定向到 /products，不用急着做复杂首页。

三、整体布局设计

用户端统一采用：

MallLayout

页面结构建议：

顶部导航栏 Header
主内容区 Main
底部 Footer（可选，一期可简化）
四、顶部导航栏设计

顶部导航要像电商，不要像现在这种侧边菜单。

建议结构：

左侧
Logo / 项目名：自营商城 MVP 1.0
可点击返回商品列表
中间
商品搜索框（一期可先只做 UI，占位或接现有搜索）
搜索按钮
右侧
商品列表
购物车
我的订单
我的地址
登录用户信息 / 登录按钮
Header 示例结构
[Logo]   [搜索框____________][搜索]
                    商品列表  购物车  我的订单  我的地址  用户名/登录
五、页面逐页设计
1. 商品列表页 /products

这是用户进入商城后的主页面。

页面目标
快速浏览商品
支持基础搜索/筛选
点击进入详情
支持直接加购物车
页面结构
A. 页面标题区
标题：全部商品
副标题：精选在售商品
B. 筛选区

一期建议只保留最基础：

关键字搜索框
状态不需要给用户
排序可后置

所以这里只要：

[搜索商品名称____________] [搜索]
C. 商品列表区

采用 卡片式布局，不要用后台表格。

每个商品卡片包含：

商品图片
商品名称
简短描述（可选）
价格
库存提示
操作按钮
商品卡片结构建议
┌────────────────────┐
│       商品图        │
│ 商品名称            │
│ 简短卖点            │
│ ￥59.90             │
│ 库存：997           │
│ [查看详情] [加购]   │
└────────────────────┘
页面重点
图片要明显
价格要突出
“查看详情”和“加入购物车”都要可点
不显示店铺ID、商品ID 这类后台信息
2. 商品详情页 /products/:id

这是最关键的成交页之一。

页面目标
让用户看懂商品
让用户愿意加入购物车
让用户准备下单
页面结构
A. 商品主信息区（左右布局）
左侧
商品主图
缩略图区域（一期可先 1 张图）
右侧
商品名称
商品副标题/卖点
价格
库存
数量选择器
操作按钮
右侧信息区建议结构
商品名称：自营｜无线鼠标 M1
商品卖点：办公静音，轻量便携
价格：￥59.90
库存：997
数量：[-] 1 [+]
[加入购物车]   [立即购买（一期可后置）]

一期如果没有“立即购买”链路，就只保留：

加入购物车
B. 商品详情说明区

用 Tab 或分块展示：

商品详情
参数信息
购买说明（可选）

一期可以先简单做成：

商品详情
--------------------
这里展示商品图文详情 / 描述文本
页面重点
操作区必须在首屏
价格和按钮要明显
库存不要藏太深
不要做成“后台详情页”
3. 购物车页 /cart
页面目标
让用户清楚知道买了什么
方便改数量/删除
可以进入结算
页面结构
A. 页面标题区
标题：我的购物车
副标题：确认商品后进入结算
B. 购物车商品列表

建议采用“行卡片”样式，而不是纯后台表格。

每行展示：

商品图片
商品名称
单价
数量
小计
删除按钮
单行结构建议
[商品图]  商品名称
         单价：￥59.90
         数量：[-] 1 [+]
         小计：￥59.90
         [删除]
C. 结算栏（固定在底部或右侧）

展示：

已选商品数
商品总额
运费（一期可显示“免运费/0元”）
应付总额
去结算按钮
结算栏建议
已选 1 件商品
商品总额：￥59.90
运费：￥0.00
应付总额：￥59.90

[去结算]
页面重点
“去结算”按钮必须明显
数量修改和删除一定要方便
不要让购物车像数据库列表
4. 提交订单页 /checkout

这是成交关键页。

页面目标
让用户确认地址和商品
让用户确认金额
让用户完成提交订单
页面结构
A. 收货地址区

显示默认地址，没有则提示新增地址。

建议结构：

收货地址
张三  138xxxx8888
河北省 保定市 竞秀区 xxx街道 xxx号

[切换地址] [新增地址]
B. 商品确认区

展示本次下单商品：

商品名称
单价
数量
小计
C. 金额汇总区

显示：

商品总额
运费
实付金额
D. 提交区

按钮：

提交订单

如果当前流程是“提交订单后再支付”，那这里就应该是：

[提交订单]

提交成功后跳到订单详情或订单列表，再进行“模拟支付”。

页面重点
地址信息必须完整
金额信息要清楚
按钮文案不要写成技术词，要像商城

例如不要写：

创建订单

应该写：

提交订单
5. 我的订单页 /orders
页面目标
让用户看到自己买过什么
能快速看状态
能继续支付 / 查看详情 / 确认收货
页面结构
A. 页面标题区
标题：我的订单
B. 状态筛选标签

建议顶部做一排：

全部
待支付
待发货
已发货
已完成

即使后端内部是 PENDING_PAYMENT / PAID / SHIPPED / COMPLETED，前端也要转成中文业务态展示。你当前盘点里也提到前后端现在更多是直接用英文枚举，产品感不够。

C. 订单列表

每个订单块展示：

订单号
下单时间
订单状态
商品列表
实付金额
操作按钮
订单块结构建议
订单号：2026041111450282001
下单时间：2026-04-11 14:50:31
状态：待发货

[商品图] 商品名称 x1
实付：￥59.90

[查看详情] [去支付/确认收货]
操作按钮规则
待支付：显示【去支付】
已发货：显示【确认收货】
已完成：显示【查看详情】
页面重点
不能只是后台表格
状态要清楚
操作按钮要跟状态走
6. 地址管理页 /addresses
页面目标
让用户维护收货地址
服务于提交订单页
页面结构
A. 页面标题
标题：我的收货地址
B. 地址列表

每个地址块展示：

收货人
手机号
完整地址
默认地址标签
操作按钮
地址块建议结构

河北省 保定市 竞秀区 xxx街道 xxx号

[编辑] [删除] [设为默认]
C. 新增地址按钮

页面顶部或底部：

[新增地址]
页面重点
地址信息要完整
默认地址要明显
操作按钮不要藏太深
7. 登录页 /login
页面目标
简洁
清楚
登录后回到用户操作链路
页面结构
登录卡片

中间居中即可：

标题：用户登录
手机号/用户名
密码
登录按钮
去注册（如果这一期有注册）
登录框建议结构
用户登录

账号
[________________]

密码
[________________]

[登录]
页面重点
不要使用商城主布局
单独用 EmptyLayout
登录成功后跳回来源页或 /products
六、用户端视觉风格建议

一期不需要做高定视觉，但要符合电商常见认知。

建议风格：

页面背景浅色
内容居中
商品卡片白底
价格用强调色
主按钮突出
卡片圆角轻一点
间距统一，不要拥挤
七、用户端组件建议

为了让页面更像产品，建议统一抽几个基础组件：

ProductCard 商品卡片
OrderCard 订单卡片
AddressCard 地址卡片
QuantitySelector 数量选择器
PageHeader 页面标题区
PriceText 价格展示组件

这样后面不会每页都写一遍。

八、一期哪些页面必须优先做像

如果你不想一次性全改，优先级建议这样：

P0
商品列表页
商品详情页
购物车页
提交订单页

这四个决定“像不像商城”。

P1
我的订单页
地址管理页

这两个决定“闭环完整度”。

P2
登录页

登录页简单做干净即可。
