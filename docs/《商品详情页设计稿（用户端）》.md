《商品详情页设计稿（用户端）》
一、页面定位

商品详情页不是展示页，是转化页。

它的核心任务只有三个：

让用户看懂这是什么商品
让用户产生购买意愿
让用户执行“加入购物车”

所以它的设计重点不是信息越多越好，而是：

商品主信息清楚
价格突出
库存明确
操作按钮明显
页面结构符合电商习惯
二、页面目标

当前一期，这个页面至少要支持：

查看商品主图
查看商品名称
查看商品价格
查看库存
选择购买数量
加入购物车
查看商品图文详情

如果后面要扩，可以再加：

商品参数
商品评价
推荐商品

但现在不必一次做全。

三、页面整体结构

建议采用标准电商详情页布局：

顶部导航 / 面包屑
商品主信息区（左右布局）
商品详情说明区
底部辅助区（可选）
四、页面结构拆解
1. 页面顶部区
1.1 面包屑导航

建议形式：

首页 / 商品列表 / 商品详情

或者：

全部商品 / 当前商品名称
作用
提供页面位置感
让用户知道自己从哪里来的
可以返回商品列表
2. 商品主信息区

这是页面最重要的部分。
建议采用：

左右双栏布局
左侧：商品图片区
右侧：商品信息与购买区
2.1 左侧：商品图片区
建议模块
商品主图大图
缩略图列表（一期可先只有1张图）
图片预览占位
结构建议
┌──────────────────────────┐
│                          │
│         商品主图          │
│                          │
└──────────────────────────┘

[缩略图1] [缩略图2] [缩略图3]
一期简化方案

如果你当前只有一张商品图，就先做：

一个大图展示区
下方不放多图切换也可以
设计重点
图片区域必须明显
比例统一
不要太小
不要挤在边角
2.2 右侧：商品信息与购买区

这是转化区，必须重点设计。

建议从上到下放这些内容：

A. 商品标题

例如：

自营｜无线静音鼠标 M1

要求：

字号明显
一眼看到商品名
不显示技术字段，不要出现商品ID
B. 商品副标题 / 卖点

例如：

轻量便携，办公静音，适合日常办公使用

要求：

1~2行即可
用于补充价值感
一期如果后端没有单独字段，可以先不做，或者复用简介
C. 价格区

价格是最重要的视觉锚点之一。

建议单独做一个价格模块：

价格
￥59.90

或者：

限时价：￥59.90
设计要求
比标题更突出
用强调色
单独成块，不要埋在一堆文本里
D. 库存信息

例如：

库存：997 件

如果库存不足，可以显示：

库存紧张，仅剩 3 件
设计要求
库存必须可见
用户要知道能不能买
不要显示技术字段 stock
E. 数量选择器

建议标准样式：

数量   [-]   1   [+]
规则
默认 1
最小 1
最大不超过库存
设计要求
简单直接
靠近加入购物车按钮
不要做成输入框让用户乱输
F. 操作按钮区

当前一期核心按钮建议只有一个主按钮：

[加入购物车]

如果你后面要扩“立即购买”，可以做成：

[加入购物车]   [立即购买]

但如果当前链路没有立即购买，就不要先加假按钮。

设计要求
按钮要大
位置要明显
在首屏内一定看到
不要藏到页面很下面
G. 辅助说明区

可放简单购买说明：

支持模拟支付流程
下单后可在订单页查看状态

或者：

发货说明：当前为一期演示版，物流轨迹功能后续完善

这块不是必须，但对演示有帮助。

商品名称

六、商品详情说明区

主信息区下面建议做“详情内容区”。

可以用 Tab，也可以直接用分区。
一期建议直接做分区，简单稳妥。

3.1 商品详情区

标题：

商品详情

内容：

商品长描述
商品图文详情
介绍说明

如果当前后端已有 detailHtml 或类似字段，就展示它。
如果没有，就先展示描述文本。

结构示例
商品详情
--------------------------------
这是一款适合办公场景使用的无线静音鼠标，
手感轻便，连接稳定，适合日常电脑办公。
3.2 商品参数区（可选）

如果一期你已经有这些字段，可以加一个简单参数模块：

商品参数
--------------------------------
品牌：xxx
型号：M1
颜色：黑色
类别：无线鼠标

没有就先不做。

3.3 购买说明区（可选）

可以简单说明：

购买说明
--------------------------------
下单后可在“我的订单”中查看订单状态。
发货后可确认收货完成订单流程。

这块对演示很友好。

七、页面布局建议

建议页面宽度采用居中布局：

页面总宽度：1200px 左右

结构可以是：

主体内容居中
左右留白
主图区和购买区横向排列
下方详情区单列展开
推荐布局比例
主信息区
左侧图片：45%
右侧信息：55%

这样更符合电商详情页常见比例。

八、页面状态设计

为了像产品，至少要考虑这几种状态。

1. 加载中状态

页面还没拿到商品详情时：

显示骨架屏
或
显示“加载中...”

不要白屏。

2. 商品不存在

当商品 ID 错误或接口返回空时：

商品不存在或已下架
[返回商品列表]
3. 商品已下架

如果商品状态不可售：

展示商品信息
按钮禁用
显示：
该商品暂不可购买
4. 库存不足

如果库存为 0：

库存：暂无库存
[加入购物车]（禁用）
九、页面组件拆分建议

为了后面可维护，建议把商品详情页拆成几个小组件。

推荐组件
1）ProductGallery

负责商品主图和缩略图。

2）ProductSummary

负责商品名称、价格、库存、卖点。

3）QuantitySelector

负责数量加减。

4）ProductActionBar

负责加入购物车按钮区。

5）ProductDetailSection

负责详情说明区。

组件结构示意
ProductDetailPage
 ├─ ProductGallery
 ├─ ProductSummary
 ├─ QuantitySelector
 ├─ ProductActionBar
 └─ ProductDetailSection

这样后面做商品页重构不会越来越乱。

十、页面跳转关系

这个页面与其他页面的关系应该很明确：

进入路径
从商品列表点击进入
从搜索结果点击进入
退出路径
返回商品列表
加入购物车成功后可：
留在当前页
或提示“去购物车”
推荐交互

点击加入购物车成功后：

方案A

弹消息提示：

已加入购物车
方案B

弹确认框：

已加入购物车
[继续浏览] [去购物车]

一期建议先做 A，简单稳定。

十一、页面文案建议

商品详情页很容易出现“技术字段感太重”的问题，所以文案要像商城。

推荐文案
标题区
商品详情
按钮
加入购物车
返回商品列表
状态
暂无库存
该商品已下架
已加入购物车
区块标题
商品详情
商品参数
购买说明
避免这种文案
查询商品详情
提交购物车项
请求成功
当前商品对象为空

这些都太技术化。
